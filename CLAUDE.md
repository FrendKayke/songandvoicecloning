# CLAUDE.md — contexte du projet Studio Voix

## En bref
Application locale Windows (Gradio) pour créer des chansons chantées avec la voix de l'utilisateur, de la musique seule, lire un texte avec sa voix (synthèse vocale), des bruitages et des modèles 3D pour un jeu.
Machine cible : PC Windows 11, RTX 4070 (12 Go de VRAM), utilisateur francophone.
Toute l'interface, les messages et la documentation sont **en français**.

## Architecture actuelle
- `studio_voix.py` : point d'entrée mince (lancé par `lancer.bat`), qui appelle `studiovoix.interface.build_ui`.
- `studiovoix/` : le code de l'application, un module par rôle :
  - `config.py` (chemins, variables d'environnement, `SR`, `LANGUES`) — les autres modules lisent `cfg.X` au moment de l'appel, ce qui permet aux tests de rediriger les dossiers ;
  - un module par moteur, chacun avec son action, `ckpt_dir()`, son état et `download()` : `acestep.py` (HTTP), `demucs.py`, `seedvc.py`, `chatterbox.py`, `nettoyage.py` et `diffusion.py` (sous-processus) ; `diffusion.py` regroupe les modèles de la même pile (diffusers/transformers) : `MODELES` (nom → dépôt HF, libellé, fichiers attendus dans le cache `HF_HOME/hub/models--…/snapshots/*/`), `lancer(action, tache, …)` relaie `PROGRESSION i/n` et lit la ligne `RESULTAT <json>` ; `bruitages.py` (description FR ou image → `decrire()` par Qwen3-VL → prompt EN modifiable → `bruitage()` : 1 à 3 variantes, `creation.json` type `bruitage`, export via `export.exporter_fichier_formats`) ; `modele3d.py` (image d'objet → `diffusion.forme3d()` ; texte → 3D = `preparer_prompt()` (Qwen mode `objet`) puis `generer_image()` (Z-Image-Turbo + `OBJET_SEUL` ajouté au prompt, `data/3d/images/<horodatage>/objet.png` + `prompt.txt`, dossiers sans `creation.json` donc ignorés par la galerie) puis la même génération, `description`/`description_fr`/`image_graine` notés dans `creation.json` ; `QUALITES` = pas / résolution d'octree / faces gardées, texture facultative, formats GLB toujours + OBJ ; `data/3d/<horodatage>/` avec `image.<ext>`, `image_detouree.png`, `forme.glb`, `modele.glb`, `creation.json` type `3d` ; la galerie affiche le GLB dans un `gr.Model3D` et recrée à partir de `image.<ext>` avec la graine ; qualité « Web léger » (10 000 faces, `web` dans la tâche → `modele_web.glb`) ; `alleger()` = action moteur `alleger` (`_alleger_glb` : textures ≤ 1024 px réencodées en JPEG — trimesh écrit en JPEG une image PIL de format JPEG —, géométrie inchangée car la simplifier casserait les UV ; testé sur un vrai GLB texturé : 12,6 Mo → 0,42 Mo ; processeur seulement, donc `lancer(..., gpu=False)` n'arrête pas ACE-Step) ; `generer_lot()` = une création par image, échecs consignés sans arrêter le lot) ; les scripts de `moteurs/` sont lancés par `outils.lancer_moteur` (protocole `PROGRESSION i/n`, `ERREUR : …`, fichier de sortie attendu) ;
  - `styles.py` : catalogue des listes déroulantes de l'onglet « Créer une chanson » (couples libellé français → termes anglais ; listes `multiselect` + `allow_custom_value`, la saisie libre passe telle quelle) ; `styles.texte()` accepte un texte ou une sélection ;
  - `jeu.py` : bande-son de jeu (catalogues `EPOQUES`, `UNIVERS`, `SITUATIONS` = libellé, description anglaise, durée, boucle ou jingle ; situation tapée librement = boucle de 90 s) ; génération en lot, une tâche ACE-Step par situation, rangée dans `data/jeux/<projet>/<situation>/<horodatage>/` (`brute.wav`, `piste.wav`, `creation.json`). ACE-Step génère au moins 10 s (`DURATION_MIN` dans `acestep/constants.py`) : les jingles sont coupés par `mixage.couper_jingle` (silence de début retiré, coupe sur le creux d'énergie le plus proche, fondu). Jamais de nom d'œuvre dans les descriptions. Cohérence : une piste du projet sert de thème, soit en `reference_audio` (timbre et mixage, text2music), soit en `src_audio` avec `task_type="cover"` et `audio_cover_strength` (variation ; `thinking` forcé à `False`, la tâche cover saute le LM ; la durée est celle du thème, donc les jingles restent en `reference_audio`) ;
  - `boucle.py` : boucles parfaites (ACE-Step ne sait pas en faire). Candidats (a, b) sur les temps de `librosa.beat.beat_track`, séparés d'un nombre entier de mesures ; on garde le couple où ce qui suit b ressemble le plus à ce qui suit a (chroma 60 %, MFCC 40 %, niveau comparable, bonus aux boucles longues) ; début recalé sur l'attaque **grave** la plus proche (± 0,6 temps : le détecteur de temps s'accroche souvent aux charlestons, à contretemps) ; b ajusté à l'échantillon près par corrélation ; la suite naturelle de b est fondue dans le début (`boucler`) pour que le fichier entier boucle. `mesure_jonction` compare le début de la boucle à la suite naturelle de b : ≈ 1 = aussi fluide qu'une répétition musicale (une répétition n'est jamais identique à l'échantillon près), ≥ 3,5 = fin mal placée. Testé sur musiques synthétiques de 80 à 170 BPM (`conftest.musique`) ;
  - `galerie.py` : liste les créations (dossiers de `SONGS_DIR`, `GAMES_DIR/*/*/*` hors `export`, `TTS_DIR`) d'après leur `creation.json` (écrit par `outils.ecrire_creation` pour les chansons, les pistes de jeu et les lectures ; les créations plus anciennes sont reconstruites depuis `prompt.txt` / `tache.json`). « Recréer » relance la création avec ses réglages et la graine de la version choisie ; « Refaire un passage » envoie `task_type="repaint"` avec `src_audio` = le fichier brut d'ACE-Step de la version (`chanson_brute.wav` ou `brute.wav`), `repainting_start`/`repainting_end` et `repaint_mode` (`conservative`/`balanced`/`aggressive`, valeurs vérifiées dans `release_task_models.py`), puis refait le traitement (`pipeline.finaliser_depuis_infos` ou `jeu.generer_piste`) dans une nouvelle création (`retouche_de`, `passage` dans son `creation.json`) ; la suppression vérifie que le dossier est bien une création sous une des racines ;
  - `export.py` : volume intégré ITU-R BS.1770-4 implémenté sans dépendance (filtre K, portes −70 LUFS et −10 LU ; identique à `pyloudnorm` au centième, qui ne sert que de référence dans les tests : `--with pyloudnorm`), normalisation avec pic plafonné à −1 dBFS (le message le signale si la cible n'est pas atteinte), OGG Vorbis et MP3 via soundfile (longueur conservée à l'échantillon près, en-tête LAME/Xing : les boucles restent exactes), pack du jeu : piste la plus récente de chaque situation (`pistes`) et, pour chaque nom de bruitage dont `creation.json` porte ce `projet`, la création la plus récente et sa variante `choisie` (`bruitages`, fichiers dans `bruitages/<id>`, identifiant ASCII sans accents, `_slug`) ; `visuels_du_projet` : pour chaque nom d'illustration du projet la création la plus récente et sa variante `choisie` (WebP s'il existe, `illustrations`), les cartes composées (`cartes`, champs repris de leur `.json`), et pour chaque nom de modèle 3D dont `creation.json` porte ce `projet` le plus récent (`modele_web.glb` > `modele.glb` > `forme.glb`, `modeles3d`), copiés tels quels ; `manifest.json` unique, archive `<projet>_pack.zip`. Les dépendances de l'application sont dans `requirements.txt` : l'étape 18 est refaite automatiquement quand ce fichier change (signature) ;
  - `voix.py` (bibliothèque de voix : `data/voices/<nom>.wav`, 44,1 kHz mono, 30 s au plus, normalisée à 0,95 ; import wav/mp3/flac ou micro avec contrôle de qualité `analyser()` — durée, niveau de la voix au 95e centile du RMS sur 50 ms, saturation —, écoute, renommage, suppression ; les noms sont comparés sans tenir compte de la casse, comme Windows, et toute opération vérifie que le nom est dans la liste), `mixage.py`, `pipeline.py` (enchaînement), `modeles.py` (tableau de l'onglet « Modèles »), `outils.py` (journal de commande, ouverture de dossier, `lancer_moteur`), `residents.py` (moteurs résidents, voir plus bas), `interface.py` (Gradio : assemble les onglets ; **un module par onglet dans `studiovoix/onglets/`**, chacun avec `construire()` — crée ses composants dans l'onglet ouvert par `build_ui` et les renvoie dans un espace de noms (`commun.espace_de_noms(locals())`, accès `c.nom`) — et `brancher(c, demo, o)` — ses événements ; `o.<onglet>.<composant>` pour les listes tenues à jour d'un onglet à l'autre (voix, modèles RVC) ; `interface.GROUPES` range les onglets en cinq groupes (🎤 Voix, 🎵 Musique, 🖼️ Image et vidéo, 🎮 Jeu, 🧰 Outils ; onglets imbriqués, un groupe d'un seul onglet sans seconde rangée), `ONGLETS` en est la liste à plat ; chaque espace de noms reçoit `onglet` et `groupe` ; **le contenu d'un onglet intérieur n'est monté qu'après l'événement `select` de son groupe** : la galerie (visionneuse 3D, voir plus haut) attend côté navigateur que sa liste soit affichée (`ATTENDRE_GALERIE`, js) avant de réafficher la création ; découpage vérifié par une empreinte de l'interface (composants dans l'ordre, événements avec entrées et sorties) identique avant et après ; onglets « Bibliothèque de voix », « Créer une chanson », « Bande-son de jeu », « Synthèse vocale », « Galerie », « Entraîner ma voix (RVC) », « Bruitages », « Modèles 3D », « Modèles » ; après chaque opération sur la bibliothèque, `synchro_voix` met à jour les listes de voix des autres onglets ; la suppression passe par un `confirm()` du navigateur).
- `moteurs/diffusion.py` : script exécuté **dans l'environnement diffusion** (`StudioVoix\diffusion`). Actions `personnage` (FLUX.2 klein, voir plus bas), `decrire` (Qwen3-VL-4B, 8,9 Go bf16, remplace le 2B ; l'étape 17 supprime le cache du 2B : modes `son` = sons d'une image, `image` = description d'objet, `bruitage`/`objet` = reformulation FR→EN ; sortie `pipe.vae.sampling_rate` = 44,1 kHz stéréo), `image` (Z-Image-Turbo, voir plus bas), `forme3d` (Hunyuan3D-2 : rembg u2net → `Hunyuan3DDiTFlowMatchingPipeline.from_pretrained(repo, subfolder=…)` + `enable_flashvdm(mc_algo="mc")` sur CUDA, appel avec `output_type="mesh"` puis `export_to_trimesh`, `octree_resolution`, `num_chunks` ; texture par `Hunyuan3DPaintPipeline.from_pretrained(HUNYUAN, subfolder="hunyuan3d-paint-v2-0-turbo")` (**diffusers 0.39 exige `trust_remote_code` pour son `custom_pipeline` local `hunyuanpaint` et son UNet `unet/modules.py`** : `_permettre_code_peintre()` l'ajoute au seul `DiffusionPipeline.from_pretrained` de `multiview_utils`, erreur constatée dans l'essai complet de l'utilisateur, reproduite et corrigée ici avec les vrais fichiers ; son UNet se charge depuis `diffusion_pytorch_model.bin`, 7,3 Go, `torch.load`), entièrement sur la carte, `enable_model_cpu_offload()` (= `--low_vram_mode`) seulement en repli sur manque de mémoire, appelée `peintre(mesh, image)`, CUDA seulement (rasteriseur) ; export GLB par trimesh, OBJ en donnant un chemin à `mesh.export` (trimesh écrit `material.mtl` et la texture PNG à côté)), `telecharger <noms…>` (`snapshot_download` avec `allow_patterns`, `detourage` = u2net de rembg). Les clés `depot`/`sous_dossier` d'une tâche permettent de tester avec un autre modèle (mini, pipeline minuscule). Une fois un modèle présent dans le cache, `HF_HUB_OFFLINE=1` évite toute requête.

Pipeline de création d'une chanson :
1. **ACE-Step 1.5** génère la chanson complète via son API REST locale (`/release_task`, `/query_result`, `/v1/audio`, `/health`, port 8001).
2. **Demucs** (`htdemucs_ft` = 4 htdemucs affinés, un par piste, `demucs.MODELE` ; `--two-stems=vocals`) sépare voix et instrumental.
3. **Seed-VC** (`inference.py`, `--f0-condition True`) convertit la voix chantée vers l'échantillon de l'utilisateur (zero-shot, 1 à 30 s de référence).
4. Mixage numpy/soundfile en 44,1 kHz stéréo, sortie dans `data/songs/<horodatage>/`.

Description (« caption ») : construite par `acestep.build_prompt` depuis les listes (**`styles.musique()`** : une saisie libre égale à un libellé du catalogue, accents et casse ignorés, ou à un synonyme français de `SYNONYMES` — médiéval, taverne, celtique… — est remplacée par ses termes anglais ; « Medieval, medievaux, medievale » tapés librement donnaient une production pop avec 44 % de l'énergie sous 120 Hz, constaté ; catalogue enrichi : médiéval, taverne, celtique, instruments d'époque, description positive seulement ; `texte()` reste neutre car les cartes l'emploient aussi), affichée et modifiable dans l'interface (`interface.apercu_description`), puis passée à `creer_chanson(description=…)`. **`use_cot_caption` et `use_cot_language` sont envoyés à `False`** : sinon le modèle de langage d'ACE-Step réécrit la description (même sans `thinking`, voir `inference.py` : `dit_input_caption = lm_generated_metadata["caption"]`) et les styles peu courants se diluent en pop. ACE-Step comprend mieux l'anglais ; son générateur n'a pas de prompt négatif (`guidance_scale` n'agit que sur les modèles « base », pas sur le turbo) : une négation (« sans basse ») ajoute l'instrument.

Client ACE-Step (`acestep.generer`) : point d'entrée unique de toutes les tâches (text2music, cover, repaint). Il choisit lui-même les graines (`use_random_seed=False`, `seed="g1,g2"` : `prepare_seeds` d'ACE-Step les applique dans l'ordre des fichiers, et `/query_result` ne renvoie pas la graine de chaque fichier), gère `batch_size` (versions, 2 au plus pour 12 Go) et envoie les fichiers audio (`reference_audio`, `src_audio`) en **multipart** : le serveur refuse les chemins absolus hors de son dossier temporaire (`validate_audio_path`). En multipart, les valeurs partent en texte (`_to_bool` du serveur relit « true »/« false »). Chaque création écrit `creation.json` (réglages, graine et dossier de chaque version).

Paroles : **`acestep.baliser_paroles`** transforme les titres de section seuls sur leur ligne (« Couplet 2 », « Refrain : », « [Pont] », « Fin »…) en balises ACE-Step (`[Verse 2]`, `[Chorus]`, `[Bridge]`, `[Outro]`) et recopie le texte de la dernière section du même nom dans une section laissée vide (« Refrain » seul) ; appliqué à la création et à « Refaire un passage ».

Retrait d'instruments (`creer_chanson(retirer=["bass", "drums"])`, liste « Retirer de la musique ») : garanti par `demucs.separate_stems` (htdemucs_ft sans `--two-stems` → `demucs4/htdemucs_ft/<morceau>/{drums,bass,other,vocals}.wav`, noms vérifiés dans `demucs/separate.py` 4.0.1) puis `mixage.mixer` des pistes gardées ; en complément, `lm_negative_prompt` (seul le modèle de langage l'utilise, donc seulement avec `thinking`). Marche dans les trois modes ; en instrumental, la piste voix (résidus) est écartée. Le faux Demucs des tests écrit une tonalité par piste (`FREQ_PISTES`) : `energie()` vérifie par FFT quelles pistes sont dans un fichier.

Modes (`pipeline.MODES`, sélecteur en haut de l'onglet) : « Chanson avec ma voix » (pipeline complet ci-dessus), « Chanson avec la voix d'ACE-Step » et « Instrumental » (étape 1 seule, résultat = `chanson_brute.wav`). L'instrumental s'obtient avec `lyrics="[Instrumental]"` : c'est le signal reconnu par ACE-Step (`acestep/api/server_utils.py`, `is_instrumental`), `/release_task` n'a pas de paramètre dédié. `interface.maj_mode` masque les réglages inutiles au mode choisi.

Synthèse vocale : `chatterbox.synthese` → `ChatterboxMultilingualTTS.from_pretrained(device, t3_model="v3")` puis `generate(text, language_id, audio_prompt_path, exaggeration, cfg_weight, temperature)` (API vérifiée dans `src/chatterbox/mtl_tts.py`), sortie 24 kHz dans `data/tts/<horodatage>/parole.wav`. `generate()` plafonne à 1000 jetons (≈ 40 s) : le texte est découpé en morceaux de 300 caractères au plus (limite de l'interface officielle), recollés avec 0,25 s de silence. Seules les 10 premières secondes de la référence sont utilisées. Chaque sortie porte le filigrane Perth.

## Règles de travail
- Vérifie les API réelles (code source, documentation des dépôts) avant d'appeler un moteur ; ne suppose pas un nom de paramètre.
- Aucun test ne peut tourner sur GPU dans ton environnement si tu n'es pas sur la machine Windows : dis clairement ce qui a été testé et ce qui ne l'a pas été.
- Pour l'installateur : analyse syntaxique et compatibilité 5.1 avec PowerShell 7 + PSScriptAnalyzer (`PSUseCompatibleSyntax`/`Commands`/`Types`, profil Windows PowerShell 5.1) ; on peut aussi l'exécuter sous Linux avec de faux `uv.exe`/`python.exe` et des fonctions qui remplacent `Invoke-WebRequest` et `Get-PSDrive`, pour vérifier l'ordre des étapes, les marqueurs et la reprise.
- Ne jamais versionner `data/` (voix et chansons personnelles) ni les `.venv`.
- Garder l'installation « un clic » : toute nouvelle dépendance ou tout nouveau modèle doit être ajouté à `installer.ps1`, à l'onglet « Modèles » et au README.
